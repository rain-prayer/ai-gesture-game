# 手势规则与稳定性设计

> 目标：在普通 USB / 笔记本摄像头上，让"抬手就跳"这件事**稳定、可预期、可解释**。

## 1. 最终映射

| 手势 | 内部状态 | 触发方式 | 游戏行为 |
|------|----------|----------|----------|
| 单手掌张开（≥3 指伸直） | `open` | 边沿触发（上升沿） | 跳跃（只有在地面时生效） |
| 双手握拳 | `crouch` | 切换（迟滞） | 下蹲 / 站起 |
| 双手张开 | `two_palms` | 边沿触发 | 二段跳（必须在空中且未用过） |
| 伸出 2 根手指 | `two_fingers` | 边沿触发 | 暂停 |
| 伸出 1 根手指 | `one_finger` | 边沿触发 | 继续 |
| 握拳 / 无人手 | `idle` | — | 静止（安全降级） |

实现位置：`game/hand_tracking.py`（分类）、`game/main.py` 的 `GestureFeeder._state_from`（多手组合）与主循环（边沿/迟滞）。

## 2. 手指伸直的判定

对食指 / 中指 / 无名指 / 小指分别比较两个距离：

```
dist(指尖, 手腕)  >  dist(指根关节, 手腕) × 1.0   →   视为伸直
```

- 指尖索引：8 / 12 / 16 / 20；指根关节：6 / 10 / 14 / 18；手腕：0；
- 大拇指不参与计数（张开与握拳时位置差异小、易误判）；
- 伸直数 `≥3` → `open`；`0` → `fist`；`1~2` → `none`。

这个规则不需要训练数据，代价是对"手掌侧对镜头""手离得很远"这类姿态不够鲁棒 —— 这些情况会落到 `idle`，而不是乱触发。

## 3. 两只手的组合

```
if 两只手都 open        → two_palms     （二段跳）
if 两只手都 fist        → crouch        （下蹲切换）
else 只看第一只手：
    伸直数 == 2        → two_fingers   （暂停）
    伸直数 == 1        → one_finger    （继续）
    手势 == open        → open          （跳跃）
    否则                → idle
```

> 注意：单手手势只看 `hands[0]`。MediaPipe 按置信度排序手部，换手会改变"主手"，因此演示时建议**全程用同一只手**。

## 4. 四层稳定性机制

| 机制 | 参数 | 解决的问题 |
|------|------|------------|
| **去抖**（debounce） | 同一手势连续 **4 帧**才写入稳定状态 | 单帧误识别导致的闪烁 |
| **边沿触发**（edge） | 只在"非跳 → 跳"的瞬间触发一次 | 手掌一直张开导致连续起跳 |
| **迟滞**（hysteresis） | 蹲：进入 2 帧 / 退出 8 帧后重新武装 | 蹲、站之间高频抖动 |
| **边界降级**（fallback） | 识别不到 → `idle`，摄像头断开 → `camera_ok=False` | 手部跟丢、光照不足、设备异常时"不乱动、不崩溃" |

摄像机取帧线程维护如下状态：

```
raw ──(连续 N 帧相同)──> stable ──(主循环读取)──> 游戏逻辑
```

主循环不直接读 `raw`，因此推理抖动不会立刻传到游戏里。

## 5. 响应延迟拆解

| 环节 | 量级 |
|------|------|
| 摄像头取帧 | 约 33 ms（30 fps） |
| MediaPipe 单帧推理 | 实测约 **9 ms**（640×480） |
| 去抖确认 | 4 帧识别结果 |
| 去抖 + 取帧累计的人体感知延迟 | 约 150–250 ms |

推理不是瓶颈；真正影响手感的是摄像头帧率、去抖窗口与玩家动作幅度。参数调整时建议**先调去抖、再调阈值**。

## 6. 演示 / 试玩建议

- 正对摄像头，手掌摊开朝向镜头，手离镜头 40–80 cm；
- 光线充足，避免逆光；背景不要有强烈的手部相似色块；
- **全程用同一只手**做单手手势；
- 二段跳要在"已经离地"之后再张双掌；
- 下蹲是**切换**语义：双拳握一下即可蹲下，再握一下站起。

## 7. 如何新增一个手势

1. 在 `hand_tracking.py` 里增加分类函数（例如用拇指与食指距离判"捏"），并给每个 hand dict 增加字段；
2. 在 `GestureFeeder._state_from` 里定义新的组合状态；
3. 在主循环中按"边沿触发 + 去抖 + 迟滞"的既有模式接入动作；
4. 更新本文档与 README 的手势表，并补充 `tools/smoke_test.py` 的规则用例。

## 8. 已知限制

- 单手手势依赖 MediaPipe 的 `hands[0]`，双手同时出现时可能改变"主手"；
- 没有深度信息，手掌前后倾斜会降低伸直判定准确率；
- 手部被遮挡（桌子、袖子）时识别会丢失；
- 目前只识别单手/双手的离散手势，不支持连续动作（如"挥手得分"）。
