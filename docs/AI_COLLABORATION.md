# 人机协作开发记录

> 这个项目的主体代码由 AI 辅助编写，但**需求、取舍、验证和拍板由人完成**。这份记录不是"用了 AI"的证明，而是"如何把 AI 的输出变成能跑、能演示、能交付的软件"的过程记录。

## 1. 协作方式

每一轮都走同一个闭环：

```
目标（我想让游戏变成什么样）
   ↓
提示词（背景 + 约束 + 验收标准）
   ↓
AI 输出（方案 / 代码 / 文档）
   ↓
我验证（读代码 → 无窗口跑 → 截图/物理推演 → 真机试玩）
   ↓
我纠错（指出具体错在哪，要求重写而不是打补丁）
   ↓
记录（本轮目标、AI 输出、验证结论、学到什么）
```

整个项目累计约 **31 轮**有效迭代，覆盖技术预研、MVP、多手势、稳定性、界面/音频、交付六个阶段。

## 2. 分工

| 我负责 | AI 负责 |
|--------|---------|
| 玩法与交互设计（手势语义、生命值、关卡节奏） | 生成主体代码（物理、渲染、菜单、存档） |
| 设定约束与验收标准 | 给出多种技术方案与对比 |
| 验证：无窗口运行、截图核对、物理推演、真机试玩 | 编写文档草稿、生成配图脚本 |
| 发现并定位 AI 的错误，决定是否接受修改 | 按指令重构、补充注释 |
| 最终拍板（加不加功能、改不改架构） | 解释原理、提供调试线索 |

## 3. AI 输出被纠正的 6 个问题

| # | 问题 | AI 初版 | 实际情况 | 修正 |
|---|------|---------|----------|------|
| 1 | 环境不可用 | 按最新 Python 3.14 安装 MediaPipe | 3.14 没有预编译 wheel，装不上 | 改用 Python 3.12 建立独立 conda 环境 |
| 2 | API 过时 | 使用旧版 `mp.solutions.hands` | MediaPipe 1.0 推荐 Tasks API | 改用 `HandLandmarker` + `BaseOptions` |
| 3 | 视频模式报错 | 直接调用 `detect()` | 连续帧必须用视频模式 | 设 `RunningMode.VIDEO` 并调用 `detect_for_video` |
| 4 | 中文全部变成方块 | 使用 Pygame 默认字体 | 默认字体不含中文字形 | 加载系统 CJK 字体并做多平台回退 |
| 5 | 蹲下时角色抽搐 | 直接修改 `rect.height` 改变碰撞盒 | 脚底随之上移，落地判定反复触发 | 改高度时保持脚底锚定 |
| 6 | 手势误触发 | 手指判定方向写反 / 阈值过松 | 掌心朝向与距离关系相反 | 改为"指尖→腕 与 指根→腕 比距离"，并加去抖 |

另外还有两类问题在迭代中被发现：

- **渲染残影**：每帧开始未清屏，快速滚动时出现拖影 → 每帧先填充背景；
- **平台穿越**：高速下落时脚底一步跨过 14 px 薄平台 → 改为扫掠式落地判定（比较前后两帧脚底位置）。

## 4. 我如何验证 AI 的输出

| 手段 | 做法 | 发现过的问题 |
|------|------|--------------|
| **读代码** | 逐个函数确认参数含义，不直接相信"应该没问题" | 手指判定方向、碰撞盒尺寸 |
| **无窗口运行** | 用 SDL dummy 驱动跑固定帧数，检查是否崩溃、状态是否合理 | 初始化顺序、字体加载异常 |
| **离屏渲染** | 用游戏自身绘制代码导出画面，逐张核对布局 | 商城按钮重叠、文字越界 |
| **物理推演** | 用公式算跳跃高度、蹲墙缺口、平台间距 | 蹲墙缺口、平台落点 |
| **真机试玩** | 对着摄像头做手势，测光照/跟丢/快挥 | 误触发、响应迟滞 |
| **边界测试** | 调暗灯光、手移出画面、快速挥手 | 确认"降级不乱动" |

现在这些检查中可自动化的部分已经固化为 `tools/smoke_test.py`（资源完整性 + 手势分类单测 + 300 帧主循环），一条命令即可回归。

## 5. AI 的能力边界

项目里有一些决定，AI 给不出正确答案，只能由人判断：

- **"这个手势好不好用"**：AI 看不到摄像头画面，也无法体会抬手的自然程度；
- **"这一关好不好玩"**：难度曲线、障碍间距、生命值数量需要真人试玩；
- **"要不要加功能"**：开发周期只有 9 天，增加敌人/金币会显著提高翻车风险，收益却不确定；
- **"演示怎么最稳"**：例如发现单手手势只看 `hands[0]` 后，决定**不改代码、改为全程用同一只手演示**，这是工程判断而不是代码问题。

因此最终的产品决策都由人拍板：

| 决策 | 结论 | 原因 |
|------|------|------|
| 失败处理 | 5 条命 + 受击 1.5 秒无敌 | 比"无敌穿墙"观感真实，又保证演示成功率 |
| 手势设计 | 一个动作一个独特手势 | 共用基础手势 + 微差区分在真实摄像头下不稳定 |
| 蹲跳高度 | 改回全高跳 | 技术力体现在机制多样性，不靠纯难度 |
| 功能范围 | 不加敌人/金币 | 周期短，打磨稳定性与交付质量收益更高 |
| 技术路线 | 升级桌面版，不重写网页版 | Pygame 不能直接跑浏览器，重写引擎风险高 |

## 6. 复盘：怎样让 AI 协作更有效

1. **给约束，而不是给愿望**："用 MediaPipe Tasks API、Python 3.12、不能联网下载素材"比"做一个手势游戏"有效得多；
2. **要求可验证的产物**：每个改动都要求"能无窗口跑 N 帧 / 能导出截图 / 给出参数表"，否则无法验收；
3. **让它解释，而不只是产出**：理解不了代码就无法定位错误；
4. **错误要指出根因**：例如"脚底离地导致落地判定反复触发"，而不是"蹲下有点怪"；
5. **保留人的判断权**：AI 可以给出 3 个方案，但选哪个、砍掉什么，必须由人决定。
